# 评审记录

发布前这个工具经过三轮独立评审。每一轮都是“请来证伪”：评审方读源码、跑测试、自己写攻击脚本。下面是每轮被找出来的问题，以及现在仍然没有验证的东西。

## 第一轮 · 0.1.1（当时叫 page-comments）

结论：不能发。

- **主张不成立**：当时主张“点 → 文件 → 回写”这个闭环值得发布。评审查到至少四个项目已经覆盖了它的不同版本。主张因此收窄为现在 README 开头那四个条件。
- **名字撞车**：已有一个同名、做同一件事的 React 工具。改名 static-html-comments。
- **三个缺陷**：损坏的批注文件被当成空文件、随后被覆盖；`/.env` 被原样提供；`--out` 让 `list` 读到 0 条。

## 第二轮 · 0.2.0

结论：主张站得住，实现还不能发。

作者当时写的是“三个缺陷都修了”，评审实测打穿了其中两处：

- 地址里用反斜杠（`/x%5C..%5C.env`），或经由一个名字正常的联接指向隐藏文件夹，仍能读到隐藏文件。
- 空的批注文件仍被当成“还没有批注”，下一次保存会覆盖它并毁掉备份。作者的自测里甚至把这个行为写成了一条通过项。

教训是只测了自己想到的写法。这一轮的攻击用例都收进了包内自测，并且确认过这些新测试拿去跑 0.2.0 时确实报错。

## 第三轮 · 0.2.1

结论：可以发。

- 上一轮的攻击用例加上新增的共 38 项，没有打穿。
- 评审方用自己写的一份页面（表格、SVG 柱状图、代码块、粘性顶栏、长页面）跑了 15 项，全过。这是除作者之外第一个用它的人。
- 提出三条要写进 README 的边界和一个 80 端口的小问题，0.2.2 已处理。

## 现在仍然没有验证的

- Windows 8.3 短文件名、文件符号链接：没有端到端实测，原因和判断见 README 的“安全”一节。
- macOS、Linux、Firefox、Safari、触屏：都没测。
- 服务跑在 80 端口：有代码支持和逻辑检查，没有实测。
- 用户：作者一人长期使用（一份 18 页的本机 HTML 讲稿，二十多条批注），评审方一人试用过一次。
